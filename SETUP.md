# Setup notes for `neelraval13/neelraval13`

This drop replaces `README.md` and adds three GitHub Actions workflows.
Here's what to do, in order, after committing the files.

## 1. Commit and push

```bash
# from your local clone
cp README.md README\(old\).md.bak  # optional, you already have one
# replace README.md with the new file
git add README.md .github/workflows/
git commit -m "feat: dashboard-style profile README with auto-updating widgets"
git push origin main
```

The README will render immediately on your profile. Most widgets (typing
SVG, capsule banner, stats cards, top-langs, streak, activity graph,
follower/star/visit badges, project pin cards) work the moment the file
is on `main` — they're all third-party services that pull live data.

The two pieces that **need a one-time action from you** are the snake
animation and WakaTime.

## 2. Enable the snake animation

The snake SVG is generated by `.github/workflows/snake.yml`. It commits
the rendered SVG to a separate branch named `output`, which the README
reads via `raw.githubusercontent.com/.../output/...svg`.

After pushing:

1. Go to your repo → **Actions** tab
2. If Actions are disabled, click "I understand my workflows, enable them"
3. Find **"Generate Snake"** in the left sidebar
4. Click **Run workflow** → confirm
5. Wait ~30 seconds for it to finish
6. Refresh your profile — snake should appear

It will then re-run automatically every 12 hours and on every push to `main`.

**If the snake image stays broken** for more than a few minutes after the
Action's first successful run, hard-refresh — GitHub caches images
aggressively. Appending `?v=2` to the snake URL in the README forces a
re-fetch.

## 3. Enable WakaTime (optional but recommended)

The `<!--START_SECTION:waka-->` block in the README is empty until the
WakaTime workflow injects content. Setup:

1. **Sign up** at <https://wakatime.com> (free).
2. **Install the WakaTime plugin in Zed** — open Zed's command palette
   (`Cmd-Shift-P`), search "extensions", install WakaTime. Paste your
   API key when prompted (find it at
   <https://wakatime.com/settings/api-key>).
3. **Make your stats public** — wakatime.com → Settings → Account →
   toggle "Display code time publicly".
4. **Add the API key as a repo secret:**
   - GitHub repo → **Settings** → **Secrets and variables** → **Actions**
   - **New repository secret**
   - Name: `WAKATIME_API_KEY`
   - Value: your key from step 2
5. Run the workflow manually once: Actions tab → **WakaTime Weekly Stats**
   → Run workflow.

It will then auto-update daily at midnight UTC. The first run looks
empty if you haven't coded with the plugin installed yet — give it a
day or two of normal coding to populate.

If you'd rather not set this up right now, **delete `.github/workflows/waka.yml`**
and remove the WakaTime section from the README (the block between
`## ⏱️ This Week I Spent My Time On` and the next `<br>`). Everything
else still works.

## 4. Known caveats / things to watch

- **Light vs dark mode.** All widgets use `bg_color=1F222E` (near-black)
  to match the pink/cyan palette. This looks great on GitHub's dark
  theme; on light theme it's a row of dark blocks on white. If a
  meaningful share of your visitors view in light mode, swap each
  `<img>` for a `<picture>` with `prefers-color-scheme` media queries.
  Happy to add this if you want — it roughly doubles the markup size.

- **External services.** The README depends on five third-party hosts:
  `capsule-render.vercel.app`, `readme-typing-svg.demolab.com`,
  `github-readme-stats.vercel.app`, `github-readme-streak-stats.herokuapp.com`,
  `github-readme-activity-graph.vercel.app`, `custom-icon-badges.demolab.com`,
  `komarev.com`, `img.shields.io`. These are the most reliable in the
  ecosystem in 2026, but any of them can have a bad day. If a widget
  shows a broken image, it's almost always a temporary outage of that
  one service — not your config.

- **Streak stats Heroku endpoint.** The streak service has historically
  bounced between Heroku and Vercel mirrors. If
  `github-readme-streak-stats.herokuapp.com` ever goes down,
  swap it for `streak-stats.demolab.com` (same params).

- **Pin cards 404.** If any of the four featured-project pin cards
  shows "Repository not found", the repo name in the README doesn't
  match your actual repo slug. Edit the `repo=` query param in the
  pin URL to match your real repo name.

- **Profile views counter resets.** `komarev.com/ghpvc/` counts from
  whenever the badge first loaded, not from the dawn of time. Don't be
  surprised if it starts at 0.

## 5. Things you might want to tune later

- **Add a "Latest Blog Posts" section** if you start writing on
  Medium / dev.to. Use `gautamkrishnar/blog-post-workflow` — same
  pattern as WakaTime, marker-comment block + a workflow that injects
  RSS items.

- **Replace the capsule banner** with a custom SVG you design in Figma
  if you want the hero to feel more uniquely yours. Save the SVG to
  `assets/banner.svg` in the repo and reference it via
  `https://raw.githubusercontent.com/neelraval13/neelraval13/main/assets/banner.svg`.

- **Expand the tech stack** if I missed anything important. The
  current list is intentionally curated to ~14 badges — adding more
  starts to dilute. If something's wrong, just edit the badge list in
  the `## 🧰 Tech Stack` section.

- **Currently** section copy is the easiest thing to keep stale. Make
  it a habit to refresh those four lines once a month or whenever your
  focus shifts.
